## 三个必须记住的坑

1. **`/c/...` 路径喂给 Windows 程序会被解析错。**
   `python -m venv /c/Users/.../envs/pvz` 报 `exit=0` 却零产出 —— Windows 版 python 把 `/c/...` 当成「当前盘根下的 `\c\...`」，环境实际建到了 `D:\c\Users\...`。
   **症状极像「沙箱拦截写入」，其实是路径格式问题。** 给 Windows 程序传路径一律写 `C:/...`。我上一条 memory 里"沙箱拦截"的诊断是错的，已修正。
   （`ls`/`grep` 这类 MSYS 工具认得 `/c/...`，所以「ls 能列出来」不能证明 Windows 程序也认得。）

2. **`conda create` 会被内置的 `safe-delete` 批量删除保护拦下。**
   报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":50,"threshold":50,"scope":"turn"}` 然后 `failed`，卡在 `Preparing transaction`（包其实已解压进 `D:\anaconda\pkgs`）。不是用户自定义钩子，`~/.workbuddy/settings.json` 里没有相关配置。
   解法：跑 conda 时用 `dangerouslyDisableSandbox: true`（需琰 授权一次）。同理，往 conda 环境里 pip 装卸包也要走这条。`settings.json` 里有 `sandbox.extraAllowWrite` 白名单，加 `D:\anaconda\envs\` 和 `D:\anaconda\pkgs\` 也许能免授权，尚未验证。

3. **conda-forge 的 pygame 不能用于本项目。**
   conda-forge 版 pygame 2.6.1 用 SDL_mixer 2.6.3，**不支持 opus**；pypvz 的 9 首 BGM 全是 `.opus`，加载即 `pygame.error: Unrecognized audio format`。
   另外它依赖 `envs\pvz\Library\bin` 里的 SDL DLL，只有 activate 后才在 PATH。
   解法：`conda install pygame` 之后要 `pip uninstall pygame` + `pip install pygame`（PyPI wheel 自带支持 opus 的 SDL2_mixer，实测 9/9 通过）。
   **结论：环境用 conda 管，pygame 用 pip 装。**

## 冒烟脚本改进了两处

- 等卡片冷却从写死 `pump(2.1)` 改成 `pump_until(lambda: card.canClick(...))` —— 写死的时间依赖倍率，估短了会随机失败。
- 种植阶段要临时 `lv.produce_sun = False` 并清空 `sun_group`：天上掉落的阳光从 y=0 往下飘会经过顶部卡片区，而 `play()` 里「捡阳光」判定在「点卡片」之前，命中就跳过卡片点击 —— 表现为随机某一行点不中卡片。这是游戏正常机制，不是 bug。
